# 输入、样式与交付

## 支持范围

| 输入 | 行为 |
|---|---|
| UTF-8 / UTF-8 BOM SRT | 保留文字、标点、显式换行；支持 `<i>` / `<b>` / `<u>` |
| 基础 WebVTT | 支持时间戳、可选 cue ID、NOTE、上述基本强调标签 |
| 单份双语 SRT | 原有上下行保留，整体使用主字幕字号 |
| 两份 SRT / VTT | 起止时间和条数严格一致，主字幕在上、次字幕在下，可设置不同字号 |
| ASS | 保留样式、特效和重叠，依赖作者提供所需字体和正确的 PlayRes |

SRT/VTT 中真实时间重叠、空字幕、倒序、超出视频的时间、ASS 精度下消失的极短 cue 都会报错。ASS 中的重叠可能是创作需求，所以不自动消除。

不支持把复杂 VTT 的 CSS、region、position 或内联卡拉 OK 时间戳静默转成普通文本。含 ASS 控制字符（反斜杠、大括号）的纯文本也会拒绝，避免它们被意外解释为排版指令；请改用经过审核的 ASS。文字中的普通 HTML 实体会解码；TAB 显示为四个空格。

默认读取字体 hmtx/cmap 的字符前进宽度，预留 10% 空间后添加显示换行，再由 libass 完成实际字形排版。这样不依赖每个 libass 构建是否为 ASS 启用 Unicode 换行。中文可在合法字符边界折行，英文单词、数字和 URL 不拆开；一个不可拆 token 仍过宽时会报错。空格可能在换行位置被换行符替代，原字幕文件不修改。

中英文可能显示多行，脚本不会为了满足行数要求擅自重新分配时间。宽度度量不等于实际字形轮廓，备用字体、加粗斜体、阿拉伯文等复杂字形需重点预览。特别长的单词/URL、窄竖屏和显式换行也需检查；严格每语言单行时使用 `--no-wrap` 并人工调整字号或提供重新确认的字幕。预计总行高超出画面会报错。

## 参数

| 参数 | 默认 / 说明 |
|---|---|
| `--font` | 必填，可重复；第一份字体为 SRT/VTT 主字体，其他为备用 |
| `--font-size` | 主字幕 em 高度占画面高的 3.8%，按字体 hhea 度量换算 ASS 标称字号 |
| `--secondary-size` | 第二语言 em 高度占画面高的 2.8% |
| `--margin` | 左右边距各占画面宽的 4.7% |
| `--bottom` | 垂直边距占高的 5.8%；顶部放置时也使用此参数 |
| `--outline` | 描边宽度占高的 0.22% |
| `--color` / `--outline-color` | `#FFFFFF` / `#000000`，命令行中用引号包住颜色 |
| `--position` | `bottom` 或 `top`，居中对齐 |
| `--no-wrap` | 仅使用输入中显式换行；默认按字体前进宽度换行 |
| `--crf` / `--preset` | `20` / `medium`；体积由内容、时长和参数共同决定 |
| `--audio` | `aac`，192 kbps；`copy` 原样复制但要求兼容 MP4 |
| `--preview` / `--start` | 样片时长与原片起点（秒）；全片交付无需这两个参数 |
| `--check` | 只校验和输出 JSON，不产生交付文件 |
| `--verify-media` | 扫描视频包覆盖范围，再完整解码音视频检查错误；长片会慢 |
| `--overwrite` | 显式允许替换四个目标文件，但仍不允许覆盖输入 |

ASS 输入的字号、颜色、边距和位置取自 ASS 本身，上述样式参数不会改写 ASS。它可能使用多个字体，应传入所有字体；其 PlayRes 由原作者定义，不机械改成原片分辨率。

## 样片与时间轴

```sh
python scripts/burn_subtitles.py --video input.mp4 --subtitles captions.srt --font font.otf --output sample.mp4 --preview 10 --start 20
```

这会渲染原片 20–30 秒区间。为保证字幕仍在正确时间出现，脚本在字幕渲染后再裁样片；从很靠后的位置抽样会读过前面的素材，速度较慢但时间轴清楚。旁边的 `.ass` 仍保持原片完整时间轴，用于后续全片重压，不应直接作为样片的外挂字幕。

SRT/VTT 毫秒边界以同一规则舍入成 ASS 百分秒，最多 ±5 ms，不人为制造相邻事件重叠。脚本不会调整说话速度、扩展片尾或用平均分配来代替真实时间戳。

## 视频与输出

- 使用第一条非封面视频流和全部音频流。其他视频流、外挂字幕流和数据流不进入交付 MP4；字幕烧在画面上。
- 输出以视频时长为上限；比视频更长的音频会在视频结束处截断。
- 默认 SDR、H.264、yuv420p、AAC、faststart。HDR PQ/HLG 会报错，需要明确的 HDR 或色调映射流程。
- 读取实际解码、自动旋转后的尺寸；非方形像素转为方形像素，奇数尺寸向下取偶数（至多改变一像素边缘尺度），确保 H.264 兼容性。
- 不强设帧率，不强制短 GOP，不保证源片体积比例，也不声称无损。高质量/特殊色彩交付需重新选择编码工作流。
- `--verify-media` 能发现常见截断和解码错误，不能证明语言准确或发现所有内容层面的缺失。包覆盖比较容忍 0.5 秒或片长的 0.1%（取较大值），异常封装/编辑列表仍可能需要人工诊断。
- 先渲染到目标目录下的临时文件，成功并验证时长后再替换目标文件；编码失败不覆盖已有成品。进程被强杀时可能留下 `.subtitle-*` 临时目录，确认无运行任务后可清理。

批量可由 AI 助手逐片执行，也可以写普通 shell / PowerShell 循环；每片用不同输出前缀。同一前缀下有 MP4、ASS、JSON 和日志，避免多个并发任务写同一前缀。

## 验收

查看至少一条长句、一处亮背景和首尾字幕，确认无裁切、方框、错误换行或关键画面遮挡。双语两个语言都检查；原片有音频时确认声音仍在。自动报告的成功只代表程序完成，不代表译文准确或视觉效果已经过人工认可。
